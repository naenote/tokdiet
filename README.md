# tokdiet

Claude Code を使っていて、利用上限に当たりやすい、あるいは何にそれほど使っているのかわからない人のためのスキルです。Claude Code が手元に残すログを読み、使用量の内訳と、減らせそうな箇所を調べます。結果は、根拠つきの改善計画として出ます。Claude は計画を出したところで止まり、あなたが承認するまで何も変更しません。

試用版です。使ってみた感想は、このリポジトリの [Issues](https://github.com/naenote/tokdiet/issues/new/choose) に書いてください。

## 最初に知っておく言葉
以降の説明で使う言葉です。

| 言葉 | 意味 |
|---|---|
| トークン | AI が文章を読み書きするときの量の単位です。おおまかには、文章が長いほど増えます |
| 上限 | Claude Code の利用上限です。契約しているプランごとの利用枠に達して、Claude Code が止まることです。枠の細かい決まりは扱いません |
| ログ | Claude Code が自分のパソコンに残す、やり取りの記録です。`~/.claude/projects` にあります |
| モデル | Claude 自体の種類です。Opus、Sonnet、Haiku があります |
| キャッシュ率 | 前に読んだ内容を、読み直さずに再利用できた割合です。低いと、同じ内容を何度も新しく読み直している可能性があります |
| 指示ファイル | `CLAUDE.md` のように、Claude に毎回読ませる決まりごとを書いたファイルです |
| スキル | 特定の作業のやり方を書いた手順書です。Claude は、各スキルの説明文を毎回読み込みます |
| MCP | 外部のツールやサービスを Claude Code につなぐ仕組みです。つなぐと、そのツールの説明が会話に載ります |
| サブエージェント | Claude が、本体の会話とは別に起動する補助の Claude です |
| 常駐オーバーヘッド | 会話のたびに、最初から自動で載る分です。指示ファイル、スキルの説明文、MCP の説明が当たります |
| compaction | 会話が長くなったとき、古い部分を要約して縮めることです |
| 管理者 | 会社やチームで、Claude の契約や利用状況を管理している人です。支出の上限やプランを決めます。個人で使っているなら、あなた自身です |
| 単価 | モデルごとの API の料金です。金額の概算にだけ使います。同梱せず、実行のたびに Claude が公式情報から取ります（後述） |
| P1、P2、…（Pn） | プロジェクト名を伏せるための匿名の番号です。P1 は 1 つめのプロジェクトを指します |
| 権限 0600 | そのファイルを、あなたのアカウントだけが読み書きできる設定です（Linux と macOS の設定です） |

## 何がわかるか
- モデル別（Opus、Sonnet、Haiku のどれをどれだけ使ったか）の使用量、キャッシュ率、ツール別（ファイルの読み込み、コマンドの実行など）、プロジェクト別（匿名の P1..Pn）。
- 無駄の原因。ログから測れたものだけを出します。
  - 常駐オーバーヘッド（指示ファイル、スキルの説明文、MCP の説明）
  - 使っていない MCP とスキル
  - 同じファイルの再読込、範囲指定なしの大ファイル読み
  - 巨大なツール結果
  - compaction の推定
  - キャッシュ率の低いセッション
  - サブエージェントの多重起動
  - 繰り返し実行される Bash コマンド
  - 上位モデルの使用割合
- 各項目は 2 つに分けます。「クイックウィン」は、品質への影響が出にくいと考えられる変更です。「要検証」は、候補を挙げるだけのもので、品質が同じかは自分のログで確かめます。
- 上限到達のエラーがログに残っていれば、その時刻と、直前 5 時間の消費トークンを出します。

出力の一部を、合成データから作ったサンプルで示します。次は `sample/synthetic-report.md` の「クイックウィン」の 1 行です。

> **同一ファイルの再読込**: Read 12 回中、同一セッションで編集を挟まず同じファイルを再度読んだ回数 8（66.7%）。回数は数えた値で、無駄かどうかは文脈次第。変更案は「再読込を避ける運用、必要範囲のみ読む」。

数えた回数と、断定できない点を分けて書くのが、この出力の形です。

## ログは外に出ません
- Python 3 の標準ライブラリだけで動きます。スクリプトはログを外へ送りません。
- 読むのはローカルのログだけです。書くのは `--out` で指定したディレクトリだけです。
- ソースは合計で約 2,000 行です。実行する前に、次のようなコマンドで通信やプロセス起動がないことを確かめられます。

```
grep -nE "socket|urllib|http\.client|subprocess" skills/tokdiet/scripts/*.py
```

## 導入
次のどちらかです。

**プラグインとして入れる**

Claude Code で次を実行します。

```
/plugin marketplace add naenote/tokdiet
/plugin install tokdiet@tokdiet
```

**スキルとしてコピーする**

```
git clone https://github.com/naenote/tokdiet.git
cp -r tokdiet/skills/tokdiet ~/.claude/skills/
```

## 使い方
Claude Code で、こう頼みます。

> tokdiet でトークンの使い方を診断して

Claude は次の順で進めます。

1. ログを集計し、詳細版の `action-brief.md`（優先アクションの一覧）を作る。
2. 各項目の根拠を、再確認コマンドで自分でも確かめる。再確認コマンドは、たとえば指示ファイルの文字数を `wc -c <ファイル>` で数え直すものです。
3. 対象、実測、変更案、確認方法を計画として出し、ここで止まる。
4. あなたが選んだ項目だけを変更する。
5. 数日から 2 週間使ったあと、前後比較で効果を測る。

Claude を使わずに直接実行することもできます。

```
python3 skills/tokdiet/scripts/tokdiet.py --out ~/tokdiet-out --snapshot ~/tokdiet-out/baseline.json
python3 skills/tokdiet/scripts/leakcheck.py ~/tokdiet-out/report.md ~/tokdiet-out/report.html --logs ~/.claude/projects
```

| オプション | 意味 |
|---|---|
| `--out DIR` | 出力先（必須）。ログやリポジトリの外を勧めます |
| `--root DIR` | 読むログの場所。既定は `~/.claude/projects`。1 プロジェクトだけ見るときは `~/.claude/projects/<proj>` |
| `--no-brief` | `action-brief.md` を作らず、匿名レポートだけ作る |
| `--snapshot FILE` | 集計のベースライン JSON を保存する（権限 0600。パスなどを含むのでローカル専用） |
| `--compare FILE` | 保存済みベースラインとの差分を、`action-brief.md` の末尾に出す |

`leakcheck.py` は、匿名レポート（`report.*`）にログ由来の情報が混ざっていないかを機械的に調べます。パス、メール、URL、ログ本文の断片、セッション ID などが対象で、1 件でも見つかれば終了コード 1 を返します。`action-brief.md` には使いません。

## 出力は 2 系統
| ファイル | 中身 | 共有 |
|---|---|---|
| `action-brief.md`（権限 0600） | 実在のスキル名、エージェント名、ファイルパス、コマンドの一部と、実測の重さ | しない。ローカル専用 |
| `report.md` / `report.html` | 集計値と匿名 ID（P1..Pn）だけ。管理者に見せる、匿名の 1 枚 | してよい。先に `leakcheck.py` で検査する |

管理者は、前の「最初に知っておく言葉」にある通り、Claude の契約や利用状況を管理している人です。`report.md` / `report.html` には、その人に渡すための要約があります。個人で使っているなら、自分で読むための要約です。

`action-brief.md` と `baseline.json` には、パス、コマンド、スキル名、エージェント名が入ります。人に渡さず、コミットもせず、Issue にも貼らないでください。共有してよいのは `report.*` だけです。

## 金額の概算と単価
`report.*` には、モデルごとの金額の概算が出ます。単価は価格表として同梱しません。実行のたびに、Claude が `claude-api` スキルで、ログに出てきたモデルの API 単価（100 万トークンあたりのドル）を読み取り、`prices.json` に書いてスクリプトへ渡します。単価は頻繁に変わるため、この方式にしています。単価はモデルごとに違うので、Opus、Sonnet、Haiku の系列ではなく、モデル ID 単位で渡します。

- 金額は、API の単価で計算した概算です。あなたの契約の請求額ではありません。
- キャッシュの読み取りは、スキルが示す金額があればそれを使い、なければ入力単価の 0.1 倍で計算します。キャッシュの作成は、入力単価の 1.25 倍（5 分）と 2 倍（1 時間）です。
- 入力が一定の長さを超えると単価が変わるモデルがありますが、その段階分は反映しません。
- 単価が取れなかったモデルは「単価不明」になり、金額に含まれません。単価をまったく渡さなければ、金額なしのレポートになります。
- Pro、Max、Team などの定額プランでは、請求額と無関係です。使用量の目安として読んでください。削減できた金額ではなく、「同じ枠でより多く使える余地」を見る数字です。

`sample/` に、合成データから作った出力例があります。サンプルの金額は、説明用の仮の単価で計算した値で、実際の価格ではありません。

## できないこと
重要なものから順に並べます。

- **削減効果の % や円は出しません。** 根拠がないからです。出すのは占有量の実測だけです。金額は API 単価での概算なので、定額プランでは「枠が広がる」と読んでください。
- **品質は測れません。** 「要検証」は、自分のログで品質が同じかを確かめる前提の候補です。
- **データが少ないと、判断を出しません。** 利用量を数えられたセッションが 5 未満なら、優先アクションは出さず「データ不足」と表示します。この閾値 5 は暫定です。ほかの閾値（巨大結果 40,000 字、範囲読み候補 20,000 字、compaction 推定の比率など）も仮置きです。
- **シークレットのマスクは正規表現ベースで、完全ではありません。** メール、JWT、秘密鍵、主要なキーの形式、`key=値` の形などを対象にします。既知の形式と違う短いパスワード、自然文に混ざった秘密、パスやスキル名に埋まった機密は検出できません。逆に、マスクしすぎることもあります。マスク済みでも `action-brief.md` は共有しないでください。
- **プラグイン経由のスキルとコマンドの呼出は推定できません。** 「呼出 0 回」や「参照 0 件」は、安全の証明になりません。スキル呼出として数えるのは Skill ツールと `<command-name>` の入力だけなので、少なく見積もっている可能性があります。組込みスキルの出所は判別できず、「不明」と出ます。
- **Bash 経由の編集は検出できません。** 再読込が成果物か参照資料かは、ログに残る Write と Edit の形跡だけで判定します。
- 他の端末や Web 版の消費は含みません。上限到達の「Time at limit」そのものは取れず、代理指標（到達直前 5 時間の消費など）だけを出します。
- スキルと MCP の個別のトークン数は測れません。スキルは説明文の文字数、MCP は通知文の総文字数で見ています。項目間で単位が揃わないので、ランキングは目安です。
- Claude Code のログ形式は非公開で、変わる可能性があります。動作を確認したのは 2026-10 時点の 1 つの環境だけで、Windows などのパス形式は未検証です。compaction の検出は実例が少なく、有効かどうか確かめられていません。
- 無効化の手順は、公式ドキュメントで確認できた範囲だけ案内します。確認できないものは「公式未確認・手順不明」と出ます。
