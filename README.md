# token-diet

Claude Code のローカルログを読み、「トークンを何に使っているか」と「上限に当たりやすい原因」を診断するツールです。自分の Claude Code の利用量や上限到達（rate limit）に悩む個人・チーム向けです。

**試用版です。** 試してみて、わかりにくかった点・役に立った点・外れていた点を教えてください（送り先: <FEEDBACK-CHANNEL>）。

## 何をするか
- `~/.claude/projects/**/*.jsonl`（`subagents/` 配下を含む）を読み、同一 requestId の重複行を畳んで集計します。
- 集計: モデル別、キャッシュ率、ツール別、匿名プロジェクト別（P1..Pn）。
- 原因別の分類（ログから測れたものだけ）: 常駐オーバーヘッド（指示ファイル・スキル説明・MCP 定義）、未使用の MCP・スキル、同一ファイルの再読込、範囲指定なしの大ファイル読み、巨大なツール結果、compaction 推定、低キャッシュ率のセッション、サブエージェントの多重起動、繰り返し Bash コマンド、上位モデルのシェア。
- 各項目を「クイックウィン（品質影響が出にくいと考えられる）」と「要検証（候補の列挙のみ。品質同等は自分のログで測る必要あり）」に仕分けます。
- 上限到達エラーがログに残っていれば、その時刻と、到達直前 5 時間の消費トークン（代理指標）を出します。

## ログは外に出ません
- Python 3 の標準ライブラリのみ。ネットワーク呼び出しはありません（価格表も同梱で、取得しません）。
- 読むのはローカルのログだけで、書くのは `--out` で指定したディレクトリだけです。
- 合計約2,000行のソース（`tokdiet.py` / `actionbrief.py` / `leakcheck.py`）なので、`grep -nE "socket|urllib|http\.client|subprocess" *.py` などで、実行前に確認できます。

## 使い方
```
python3 tokdiet.py --out <リポジトリ外のディレクトリ>
python3 leakcheck.py <out>/report.md <out>/report.html --logs ~/.claude/projects
```
| オプション | 意味 |
|---|---|
| `--out DIR` | 出力先（必須）。ログやリポジトリの外を推奨 |
| `--root DIR` | 読むログのルート。既定は `~/.claude/projects`。特定プロジェクトだけ見たいときは `~/.claude/projects/<proj>` |
| `--no-brief` | `action-brief.md` を作らない（匿名レポートのみ） |
| `--snapshot FILE` | 集計のベースライン JSON を保存（0600・パス等を含むローカル専用） |
| `--compare FILE` | 保存済みベースラインとの差分を `action-brief.md` 末尾に出す |
| `leakcheck.py` | 匿名レポート（`report.*`）にログ由来の情報（パス・メール・URL・ログ本文の断片・セッション ID など）が混入していないか機械検査。1 件でも検出すれば終了コード 1。`action-brief.md` には使いません |

テスト: `python3 -B -m unittest discover -s tests`

## 出力は 2 系統
| ファイル | 中身 | 共有 |
|---|---|---|
| `action-brief.md`（0600） | 実在のスキル名・エージェント名・ファイルパス・コマンド断片と、実測の重さ | **ローカル専用。共有しない** |
| `report.md` / `report.html` | 集計値のみ・匿名 ID（P1..Pn）。管理者への転送用 | 可（`leakcheck.py` で検査してから） |

`action-brief.md` と `baseline.json` には、パス・コマンド・スキル名・エージェント名が入ります。人や公開リポジトリに渡さないでください。渡すのは `report.*` だけです。

## 自分の Claude に action-brief を読ませる
1. `python3 tokdiet.py --out ~/tokdiet-out --snapshot ~/tokdiet-out/baseline.json`
2. Claude Code で `~/tokdiet-out/action-brief.md` を読ませる。ファイル冒頭に「各項目の根拠を再確認してから、変更案を出し、変更前後で測れるようにして」という指示が入っています。
3. 各項目に付いた再確認コマンドで根拠を自分でも確かめ、納得したものだけ変更する。
4. 数日〜2 週間使ったあと `--compare ~/tokdiet-out/baseline.json` 付きで再実行し、該当指標が下がったかを見る。

出力の主な内容: 優先アクション上位 10（実測の重さ順。対象／重さ／再確認コマンド／リスク区分／変更案／変更後の確認方法）、実測の重い順 上位 5、スキル表（説明文の長さ・期間内の呼出回数・出所・編集可否）、サブエージェント種別、再読込・範囲指定なし読みのファイル、指示ファイルの節別サイズ、反復 Bash、MCP ツール別。「要検証」項目には、同じ実入力 3 件を変更前後で流して比べる最小手順が付きます。

`sample/` に、合成データから作った出力例があります。

## できないこと・限界
- **削減効果の %・円は出しません。** 根拠がないためです。出すのは占有量（実測）のみです。金額表示は API 単価での概算で、定額プランでは「枠の拡大」として読んでください。
- **品質は測れません。** 「要検証」は、自分のログで品質同等を確かめる前提の候補です。
- **Bash 経由の編集は検出できません。** 再読込が成果物か参照資料かの判定は、ログ上の Write/Edit の形跡のみが根拠です。
- **プラグイン経由のスキル・コマンド呼出は推定できません。** 「呼出 0 回」「参照 0 件」は安全の証明ではありません。スキル呼出として数えるのは Skill ツールと `<command-name>` 入力のみで、過小評価の可能性があります。組込みスキルの出所は判別できず「不明」と出ます。
- **データが少ないと判断を出しません。** 利用量を数えられたセッションが 5 未満なら、優先アクションは出さず「データ不足」と表示します。この **閾値 5 は暫定** です。他の閾値（巨大結果 40,000 字、範囲読み候補 20,000 字、compaction 推定の比率など）も仮置きです。
- **シークレットのマスクは正規表現ベースで完全ではありません。** メール・JWT・秘密鍵・主要なキー形式・`key=値` 形式などを対象にしますが、既知の形式と違う短いパスワード、自然文に混ざった秘密、パスやスキル名に埋まった機密は検出できず、過剰マスクもあります。マスク済みでも `action-brief.md` は共有しないでください。
- 他端末・Web 版の消費は含まれません。上限到達の「Time at limit」そのものは取れず、代理指標（到達直前 5 時間の消費など）のみです。
- スキル・MCP 定義の個別トークン数は測れません（スキルは説明文字数、MCP は通知文の総文字数）。項目間の「重さ」は単位が揃わないため、ランキングは目安です。
- Claude Code のログ形式は非公開で、変わる可能性があります。動作確認は 2026-10 時点の一つの環境のみで、Windows 等のパス形式は未検証です。compaction 検出は実例が少なく有効性が未検証です。金額の単価表（`PRICES`）は公式で再確認していません。
- 無効化手順の案内は公式ドキュメントで確認できた範囲のみで、確認できないものは「公式未確認・手順不明」と出します。
